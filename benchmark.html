Three tasks

What you can be scored on

Each task uses the community's standard protocol, so existing methods and evaluation code plug in unchanged.

2D object detection

COCO
You predict
A box, class and score for each object, as a COCO results file.
Primary score
AP averaged over IoU 0.50 to 0.95
Also reported
AP50, AP75, AP for small, medium and large objects, AR at 300 detections

Instance segmentation

COCO
You predict
An RLE mask, class and score for each object, as a COCO results file.
Primary score
Mask AP averaged over IoU 0.50 to 0.95
Also reported
AP50, AP75, AP by object size, AR at 300 detections

6D object pose

BOP
You predict
Rotation, translation in mm, object id, score and run time per image, as a BOP CSV.
Primary score
AP6D, the mean of APMSSD and APMSPD (BOP 2024)
Also reported
AR6D (BOP 2019). Symmetric objects are scored with their symmetries.

Take part

From predictions to the leaderboard

The same command checks your file, scores it and writes the card you cite, so a reported number can always be traced back to the exact ground truth and predictions.

  1. Get the benchmark

    Install the evaluator and download the v1.0 files. verify confirms your copy of the ground truth is the frozen one.

  2. Train and tune

    Train on train and tune on val. No test frame, test annotation or frame from a test block may be used.

  3. Predict on the test frames

    Run on the frames in splits/test_eval.txt: a COCO results file for detection and segmentation, a BOP CSV with the run time of each image for pose.

  4. Score and submit

    validate catches format mistakes, eval writes the result card with a ready-made table row for your paper. Open an issue on the benchmark repository with the card attached.

take_part.sh
# 1. get the benchmark
pip install git+https://github.com/KITchen-Dataset/kitchenbench@v1.0
unzip kitchen_bench_v1.0.zip
kitchenbench verify kitchen_bench_v1.0

# 3. describe your method once
kitchenbench method-template > method.json

# 4. check and score (det, segm or pose)
kitchenbench validate kitchen_bench_v1.0 pose my_poses.csv
kitchenbench eval     kitchen_bench_v1.0 pose my_poses.csv --method method.json
# results/my-method_pose_test.json  .md  .tex

Fair comparison

Rules and splits

Rules

  • Report the version with every number, for example "KITchen v1.0 AP6D".
  • State the input and all training data, pretraining included. Pose methods using RGB and RGB-D are ranked separately.
  • One model for all objects for pose, as in the KITchen paper.
  • At least 5 fps for pose, measured as wall time per image on the hardware you state.
  • Pose methods that meet both paper rules rank first. The others are listed below them.

How the splits are made

  • Whole blocks of 250 frames go to train, validation or test (70%, 10% and 20% of the blocks, fixed seed), because consecutive frames are near-duplicates.
  • 25 train frames are dropped on each side of a validation or test block.
  • Every 6th frame of the test blocks is scored.
  • The test ground truth is public and the evaluator is frozen and versioned. New annotations always mean a new version.

Benchmark files v1.0

One archive with everything the evaluator needs. The images come from the dataset download.

  • Splits train, validation and test frame lists, plus the scored test frames
  • 2D ground truth COCO files with boxes, masks and ignore regions
  • 6D ground truth BOP files with poses and the pairs left out of scoring
  • Evaluation models with their symmetries
  • Manifest benchmark.json with the checksum of every file
